# Приёмный клиент и предложения через ревью

Состояние проверено 14 октября 2026: основная ветка `master` этого репозитория
не защищена branch protection, rulesets отсутствуют. **Само наличие этой инструкции
не включает обязательное ревью в GitHub.**

## Сейчас: только получение

Первый путь, публичный ZIP и работа в отдельной личной папке. Новому участнику не
выдают upstream write/admin, credential владельца или deploy key с записью.
Папка `lite` не меняется агентом; это ограничение задачи, не файловая sandbox.
Личные результаты и заметки не публикуются и не попадают в обновления набора.

Даже Git-клон сам по себе не является read-only: если на машине есть аккаунт с правом
записи, push может пройти. Поэтому клонирование с credential владельца не подтверждает
приёмный режим. Для первого теста достаточно ZIP без подключения GitHub к агенту.

## Позже: право предложить, без права применить

Только после прямой просьбы владельца участник использует свой отдельный аккаунт
и fork. Агент готовит одну локальную правку, показывает diff и проверку, затем с
разрешения участника отправляет ветку и PR. Участник не получает upstream write.
PR проверяет другой человек или вендор; сопровождающий принимает решение о слиянии.
Автор не считает собственное ревью независимой проверкой.

Участник может коммитить у себя. Приёмные клиенты получают новую версию только
после решения о слиянии. Приватные материалы, реальные карточки людей, пароли и
настройки владельца остаются за пределами предложения.

## Если владелец решит технически закрепить ревью

Перед выдачей прав записи в upstream владелец отдельно утверждает изменение настроек:

| Настройка основной ветки | Требование |
|---|---|
| Require a pull request before merging | Включено |
| Required approving reviews | Не меньше одного независимого ревьюера |
| Dismiss stale approvals / approval of latest push | Новая правка требует актуального ревью |
| Force pushes / deletions | Запрещены |
| Bypass / администраторы | Явно названные исключения; без исключения у нового участника |

Назначьте реального ревьюера с правом одобрения **до** включения требования.
Самоодобрение владельцем собственного PR не заменяет независимого ревью.
Техническое правило, подтверждённая настройка GitHub, а не обещание в README.
В этом изменении настройки репозитория не меняются.

После настройки подтвердите API/UI чтением и пробным PR: без одобрения merge
недоступен, после новой правки требуется новое одобрение, прямой push от участника
не проходит. Выполняйте такой тест только с отдельным тестовым участником и
разрешением владельца; права администратора исказят проверку.

См. [GitHub: protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)
и [формат предложений](HOW-TO-CONTRIBUTE.md).
