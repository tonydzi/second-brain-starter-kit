LLM_WAVE — волна аутрича топ-LLM вендорам отдельными сессиями (anton 27.07)

ЦЕЛЬ: конвейер Миссии №2 — регулярно и стандартно заходить во все живые экосистемы топ-10 LLM через issue-matching, каждый вендор = своя сессия, хвосты не теряются.

ШАГИ:

1. RECALL ПОСТРОЕННОГО (0 токенов сперва): MEMORY.md-строки 🚀 (наши PR + статусы) → [[oss-backlog-multi-vendor-wave2]] (живые двери + скипы с причинами) → дашборд `$OBSIDIAN_VAULT/_Dashboards/LLM-Cookbook-Radar.html` → открытые DR по волне (dr_registry). НЕ предлагать вендора из скип-листа, не проверив, что причина скипа устарела.

2. ПРЕРЫВАНИЕ-ЧЕК (правило №1): живые ответы людей на наши открытые PR (`gh pr view` по реестру / pr_watch). Есть ответ → сперва он (same-day), волна после.

3. LIVENESS-ВЕТО на каждый анкер-кандидат СЕГОДНЯ (память ≠ живое состояние): `gh issue view <n> --repo <vendor/repo> --json state,title` — анкер OPEN? конкурирующий PR не появился? репо мержит внешние PR (последние merged)? Радар протух (>7 дней) → сперва `~/llm-cookbook-radar/scan2.sh`. ⚠️ Грабли: GitHub search >5 OR = молча 0; Google Copybara — «closed unmerged» бывает влит (читать комменты).

4. ВЫБОР ЦЕЛЕЙ ВОЛНЫ по правилам (все = канон, не вкус):
   - только issue-matched анкер (чья-то живая просьба; без анкера = антипаттерн, в бэклог);
   - первый PR в НОВУЮ экосистему > второго в старую; один репо не флудить (ждать ревью);
   - только порты ГОТОВЫХ наших паттернов (authority routing #787, consensus #784, pipeline-vs-barrier #788, citation #789, verified-ops #70) + живой прогон; новьё с нуля = не волна;
   - потолок ~3 пишущих сессии за раз (§9.2).

5. СИД ОТДЕЛЬНОЙ СЕССИИ на каждого вендора (spawn_task, cwd=~/chips-playground — из GDrive-workdir падает WorktreeCreate): сид самодостаточен — Outcome (PR закрывает issue #N) · Контекст (анкер-линк, наш паттерн-источник, прецеденты репо, CONTRIBUTING/CLA-грабли) · Scope · DoD (PR открыт + /tt + кредит автору анкера в описании + журнал/вахта) · не-цели (не трогать соседние PR, не флудить) · эскалация (CLA/Tier-2 → Антон). В сид ВПИСАТЬ: прогнать /outbound-gate перед ship; ⛔ в Google-репо НЕ ставить Co-Authored-By Claude (CLA требует подпись всех авторов).

6. ЖУРНАЛ + ВАХТА: каждой цели — строка в MEMORY.md (🚀 после ship) + PR в pr_watch; сиды = моя эстафета (Connect): на чекине карта «сиды → чего добились».

ОТЧЁТ Антону (ELI5): какие вендоры взяли и почему (анкер-линк) · кого скипнули и почему · какие сессии посеяны · что на вахте.
