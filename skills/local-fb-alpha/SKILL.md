# /fb-alpha — альфа из комментов FB-поста: достать, протестировать, разложить

**Зачем.** Под постами Антона комьюнити бесплатно приносит prior-art, инструменты и лидов. Замер 31.07 (пост про анти-слоп): 8 комментов дали 3 рабочих репо (32k⭐ один), незакрытую проблему (деепричастия), обещание пошерить библиотеку скиллов и 6 живых AI-практиков. Всё это ТОНЕТ, если просто прочитать и кивнуть. Скилл превращает комменты в проверенные артефакты.

**Главный принцип: ссылка не записывается — ссылка ТЕСТИРУЕТСЯ.** «Живой URL ≠ проверенная цитата» [[live-url-is-not-a-verified-citation]]: чужое «там всё решено» — это claim, проверяем фактом (fetch → правила → сравнение с нашим).

## Шаги

### 1. Вход — дамп комментов
Источники по убыванию удобства: (а) Антон вставил текст в чат (как 31.07); (б) свежий отчёт `/fb-watch`; (в) живая вкладка Chrome → лента `facebook.com/notifications` (⛔ IP-гейт не мешает — это ЧТЕНИЕ; писать отсюда нельзя). Из дампа выдёргиваем: автор · текст · ссылки · это ответ Антона или чужой коммент (реплики самого Антона = контекст, не альфа).

### 2. Классификация каждого коммента (детерминированно, 4 корзины)
- **АРТЕФАКТ** — ссылка на репо/тул/статью/доку → корзина тестирования (шаг 3).
- **ЛИД-СИГНАЛ** — человек написал содержательное / предложил что-то / задал вопрос → корзина людей (шаг 4).
- **ОБЕЩАНИЕ/ХВОСТ** — «могу пошерить», «скину в личку», вопрос Антона без ответа → корзина хвостов (шаг 5).
- **ШУМ** — лайк-словами, флейм, оффтоп → мимо, не тащим.
Один коммент может попасть в 2 корзины ([человек] 31.07 = лид + обещание).

### 3. Тест артефактов — сердце скилла
На каждый артефакт, БЕЗ пропусков:
1. `WebFetch` репо/страницы → что это, правила/подход, ⭐, свежесть, язык.
2. **Сравнить с нашим аналогом** (RECALL: какой наш скилл/скрипт делает то же?). Формат вердикта — таблица:
   `наше правило есть у них? · их ход, которого нет у нас · вердикт: берём/дубль/мусор`.
3. «Берём» = правка нашего артефакта В ТОТ ЖЕ ЗАХОД (пример: правило деепричастий из humanizer-ru → ai-slop §Альфа 31.07), не заметка «посмотреть потом».
4. Спорное/большое → кандидат в `/tt` или мини-DR, но это исключение — дефолт «проверил сейчас».
⚠️ Названный без ссылки инструмент («скилл humanizer») — сначала найти точный URL (поиск), потом тестировать; «не нашёл» ≠ «нет» [[check-all-places-not-one]].

### 4. Люди — сверка с CRM
По каждому автору из корзины лидов:
```bash
ls "$OBSIDIAN_VAULT/07-People/" | grep -i <фамилия>     # карточка есть?
```
+ RECALL (лид-карточка CRM, переписка, `outreach_log.py check`). Выход — таблица: `имя · карточка есть/нет · relationship · чем занимается (из коммента+карточки) · AI-вайбкодер? · след. ход`. След. ход НЕ исполняется этим скиллом — передаётся в `/fb-reply` (коммент) или `/local-fb-messenger` (DM), это их юрисдикция и их гейты.

### 5. Хвосты — в реестр, не в память сессии
Каждое обещание/незакрытый вопрос → задача `10-Tasks/task-*.md` (или строка в существующую) с источником-ссылкой на коммент. Правило Connect: «Антон попросил пошерить» без трекинга = потерянный вклад.

### 6. Выход одним блоком
Отчёт Антону: «🧪 артефактов N (взяли X ходов) · 👤 лидов M (из них K новых) · 📋 хвостов J → задачи · уроки → дома». Уроки — по матрице домов (§8.4), правку чужих скиллов регистрировать.

## Границы
- Скилл ничего не постит и не шлёт — read + test + route. Исходящее = /fb-reply и /local-fb-messenger со своими гейтами.
- Приватные данные комментаторов не утекают в публичные артефакты (в скилл/GitHub идут уроки, не имена без нужды).
- Тестирование чужого кода = чтение/фетч, НЕ запуск непроверенного кода на машине; запускать только после ревью глазами.
