# /adopt — доказательное внедрение внешней альфы

> 🧒 В конце ответа Антону — «Простыми словами».

HARVEST нашёл ценную идею. ADOPT решает: станет она живым процессом или архивной заметкой. Не ритуал заметок — **реестр + тест на реальных данных + гейт продвижения**. Каждая стадия стоит на уже готовом правиле (не строим второй движок).

## Модель: gated state machine (не линейная лесенка)

```
INTAKE → MAP → TEST → TRIAL → PROMOTE → VERIFY
```
Терминалы (в любой момент): **DROP · CONFIRMED_EXISTING · SUPERSEDED · RETIRED**

⛔ Два железных правила из DR:
- **DROP возможен на КАЖДОМ гейте** (после MAP/TEST/TRIAL/VERIFY), не только финалом.
- **VERIFY — отдельная стадия**, не внутри PROMOTE (иначе «внедрённое» = тихий мёртвый код).

## Стадии (и на чём стоят)

**0. INTAKE.** Идея пришла из HARVEST/наблюдения/DR. Одна строка: что за альфа, откуда, почему ценна.

**1. MAP + no-op check.** Переведи альфу в **changed mechanism** (Rule / Skill / Hook / Field / Rubric / Eval / Dashboard-query / Checklist). Не выражается механизмом → остаётся знанием, не процессом → DROP-в-знание.
No-op check (обязателен ДО теста): механизм + триггер + потребитель + доказательство уже есть?
→ всё есть = **CONFIRMED_EXISTING** (не строим, линкуем доказательство). Частично = достроить недостающее. Нет = NEW_ADOPTION.
Рычаг: [[capture-rules-into-bible]] (маршрутизация в дом).

**2. TEST (before→after на РЕАЛЬНЫХ данных).** Детерминированный скан/замер, не «кажется лучше». Зафиксируй baseline. Для агент/RAG-изменений — исторический replay + regression. Рычаг: [[show-before-after]].

**3. TRIAL (испытательный срок).** Time-boxed, окно по частоте (daily 7–14д/≥10 срабатываний · weekly 4–6нед/≥6 · rare 2–3мес/≥3). Меряй: adherence (использований / возможностей) · fidelity (core-шаги сделаны) · friction. Рычаг: `alpha-trial-relay` (KEEP/DROP слоты).

**4. PROMOTE.** Внедри как durable-артефакт (правило/скилл/хук/поле/шаблон/eval/чек-лист) + rollback-правило. ⛔ Гейт: **named consumer обязателен** — назови кто/что это потребляет, иначе чёрная дыра. Рычаг: [[connect-rule-pipeline-ownership]] + `/tt` (done-gate).

**5. VERIFY.** Потребитель РЕАЛЬНО использует? Проверь D+7/D+30/D+90 retention. Держим / упрощаем / выбрасываем / заменяем.

**Терминалы:** DROP → [[declined-decisions]] (anti-reinfection: причина + reconsider-if). SUPERSEDED/RETIRED → устаревшее правило заменено/снято.

## Классификация провала (при DROP/adapt)
Плохая альфа→DROP · плохой mapping→remap · плохой тест→redesign · плохое внедрение (хорошая идея, кривой триггер)→adapt · нет потребителя→assign/retire · контекст не наш→DROP. Различай **провал идеи** vs **провал внедрения** (не выбрасывай хорошую идею из-за кривого интерфейса).

## AK-47 границы
v1 = костяк выше. НЕ тащить сразу: YAML adopt-cards, Dataview-дашборд, eval-датасеты, telemetry-логи — подключать по мере надобности, когда заболит (DR сам предупреждает про schema-bloat / over-automation). Скилл = локальный слой, канон в Библию — только предложением через хаб.

## Пороги (пре-регистрируй ДО теста, практические не p-value)
KEEP если: success_delta ≥ заметный (напр. ≥20% или +1 балл рубрики) · adherence ≥70% · fidelity ≥80% · нет пробоя guardrail · consumer использовал ≥3 раза.
DROP если: пробой guardrail · adherence <50% · нет named consumer · нет выгоды после min-возможностей · поддержка дороже пользы.

## Периодическая уборка (уже есть рычаги)
Раз в ~90 дней (на /arch + memory-tidy): промо-артефакты без использования потребителем 30д / без verify 90д / поля без запроса / скиллы без успешного вызова / правила ни разу не сработали → KEEP/SIMPLIFY/MERGE/SUPERSEDE/RETIRE.
