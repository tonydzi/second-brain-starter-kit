# /to-call — довести тёплого лида до звонка

> Боль (26.07): 5 человек сказали «давай», но 1 внутри и 0 звонков. Разрыв воронки = между
> «да» и «созвонились». /leads показывает и пишет ответ; ЭТОТ скилл именно ЗАКРЫВАЕТ на звонок.
> Правило: Антон продаёт отлично голосом, но избегает касания ([[anton-sales-avoidance-root]]) —
> моя работа снять всё трение, ему оставить только «взять трубку».

## ⚖️ Канон корпоративной Библии (звонки) — выстраданные правила Platinum

Источник истины = волт (читать при исполнении, здесь только суть + указатель):

1. **Окно 48 часов** — после «да» или звонка интерес лида живёт ~48ч, дальше коммиты
   отзываются. Следующий шаг (слот/звонок) букается ДО закрытия окна. Каждый звонок
   продаёт СЛЕДУЮЩИЙ звонок: недосказанность · анонс Антона («на следующем будет Антон») ·
   конкретная польза («принесу анализ X / интро к Y»). Завершить касание без конкретного
   следующего шага = потеря лида. → `insight-sell-next-call`
2. **CTA железно** — КАЖДОЕ сообщение лиду содержит call-to-action; без CTA шлём только
   когда CTA-чек-лист исчерпан (и помечаем — больше не допинговать). Чек-лист «что нам
   надо от лида» по типу (инвестор/фаундер: созвон touch base · интро к его инвесторам ·
   позвать на Collective Calls · «на какие топики можешь говорить вечно?») →
   `tg-2024-02-19-1222` (чек-лист call-to-action) + `2024-02-19--когда-мы-пишем-лиду…`
   ⛔ **ГРАНИЦА (DR26-07-26, 2 движка):** правило живёт в АКТИВНОМ треде. В **реанимации**
   первое касание идёт БЕЗ ask'а — сообщение с CTA и без новой ценности неотличимо от
   «just checking in», который оба движка называют худшим классом (жжёт контакт).
3. **Лестница касаний** (протокол холодного питчинга): касание 1 = ценность/повод →
   касание 2 = продолжение → интервал 1–2 дня. **Молчащему холодному Calendly-ask не раньше
   4–5-го сообщения** (ранний meeting-ask на холодных снижает конверсию — DR26-07-26+Gong);
   **ответил содержательно → счёт обнуляется**, сказал «да» → слот сразу (окно 48ч, п.1).
   Перед новым касанием — ЧИСТКА треда: наши неотвеченные/непрочитанные старые сообщения
   удалить, тред заканчивается двусторонним диалогом или пуст. Запрещено: «how are you?»,
   3+ сообщения подряд, сообщение без связи с историей чата. → `protocol-cold-pitching`
   ⚠️ **Уточнение (DR26-07-26):** лестница — про ХОЛОДНОЕ. После явного «да» слот идёт
   **в том же треде сразу**, не «через 1–2 дня» (Gong 304k: внутри активной сделки
   конкретный CTA с датой/временем 37% success vs 28% у размытых).
4. **Допинг неотвеченных** — сообщение с CTA без ответа не бросаем: пингуем/переотправляем
   (по лестнице п.3, не спамом), пока чек-лист CTA не исчерпан. → `2024-02-19--когда-мы-пишем-лиду…`
   ⚠️ **Доза (DR26-07-26):** в реанимации ≤3 СОДЕРЖАТЕЛЬНЫХ касания за 2–3 недели, дальше
   снять с активной погони до реального триггер-события. «Пока чек-лист не исчерпан» без
   потолка = убывающая отдача и выжигание контакта.
5. **Букинг-механика** — Calendly лида читаю САМ (публичный API, 0 токенов): его таймзона +
   открытые слоты; слот свободен ОБОИМ, ±30 мин до/после любого события по ОБОИМ календарям
   (bb + a2); окно матчинга 06:00–24:00 Лиссабон; время показываю в поясе Антона И в поясе
   лида; букаю только после «+», НИКОГДА молча. → `reglament-buking-zvonkov-bb-platinum`
6. **Окно отправки** — лиду пишем только 08:00–23:00 по локальному времени Антона; табу
   02:00–06:00 даже если лид написал ночью (палит автоматизацию). Ночной черновик → очередь
   на утро. → `reglament-warm-window-08-23-chasy-antona`
7. **Частота и переносы** — звонки с проектами ≤1/6мес, с VC/инвесторами ≤1/мес; перенос
   день-в-день запрещён, уведомление ≥24ч, перенос только через Антона. → `protocol-call-planning-scheduling`
8. **После звонка = в тот же день** — письменный follow-up с блоком **Promised** (Agreed →
   Promised, обе стороны, с деталями; устное без записи = время впустую) и крючком на
   следующий звонок прямо в ФА («agreed to discuss X on the next call — pls give calendly»);
   выполнить обещанное сразу; решение/ask запрашивать СРАЗУ, пока лид тёплый — промедление
   убивает коммит. → `protocol-followup-structure` + `protocol-post-call-actions` + `protocol-second-third-call`
9. **Touch-base ритм** (принято anton 27.07): verified-лид без звонка >3–6 мес → назначаем
   touch base БЕЗ повода-питча — повод = сам ритм («давно не общались, освежим кто что
   делает»). Ключ к реанимации gold-зависших. При активном фандрейзе инвесторы «не
   выгорают» — писать до ответа. → `protocol-investor-lead-pipeline`
   ✅ **СШИВКА ПРИНЯТА АНТОНОМ 19.08.2026** (`origin: anton`, supersedes формулировку
   «повод = сам ритм» от 27.07). Основание: DR26-07-26, оба движка независимо — для
   получателя «повод = сам ритм» неотличим от «just checking in», худшего измеренного
   класса касаний. **Действующее правило:** ритм решает **КОГДА** писать, конкретная
   дельта/артефакт решает **ЧТО** написать. Пустое «давно не общались» **не отправляем
   никогда** — нет дельты, значит ход не наступил, ищем дельту или ждём.
   При активном фандрейзе частота инвесторам сохраняется (пишем до ответа), но каждое
   касание всё равно несёт свою дельту.
10. **No-show-протекция**: звонок забукан → напомнить лиду за 24ч И за 1ч; не пришёл →
    вызванивать, ждать 10 мин, скрин подтверждения присутствия. → `protocol-lead-qualification-call`
11. **DoD звонка**: без полученного Telegram/WhatsApp лида звонок НЕ ЗАСЧИТАН; следующий
    звонок букается в конце текущего + недосказанность («посмотрим X — давайте забукаем
    следующий»). → `protocol-lead-qualification-call`

## Когда сам (проактивно, без просьбы)
Лид с сигналом «созрел до звонка, но завис»:
- ответил «да/давай/интересно» → **прошло 24ч без забуканного шага** (окно 48ч закрывается — канон п.1);
- Calendly/слот предложен → не забронировал 24ч+;
- advisor принял инвайт но не зашёл; тёплый партнёр молчит на 2-е касание;
- прошёл звонок → в тот же день нет ФА с Promised-блоком (канон п.8);
- **verified-лид без звонка >3–6 мес** → ритм говорит «пора» (канон п.9) → ищу конкретную
  дельту/артефакт под этого человека; **дельты нет → касание не отправляю**, а ставлю
  задачу «найти дельту» (сшивка, anton 19.08);
- **звонок в календаре <24ч** → проверить, что напоминания 24ч/1ч стоят (канон п.10).

## Порядок (8 шагов)

1. **ЖУРНАЛ + дедуп.** `python3 ~/Obsidian/Anton-Knowledge/_outreach/outreach_log.py check "<имя/handle>"` —
   что уже писали, сколько касаний, есть ли долг ответа С НАШЕЙ стороны ([[outreach-relationship-debt-gate]]).
2. **RECALL контекст.** Карточка `07-People/person-*.md` + живой тред (Telegram MCP get_history
   по самому тёплому аккаунту). Найти РЕАЛЬНЫЙ повод для звонка из истории, не шаблон.
3. **Считать сигнал стадии.** Текст ещё живой (отвечает, но тянет) ИЛИ замолчал совсем?
   → определяет канал (шаг 4).
4. **ВЫБОР КАНАЛА (ядро скилла):**
   - **Текст ещё работает** → предложить ОДИН конкретный слот («[человек] 17:00 по тебе?»),
     не «когда удобно» (открытый вопрос убивает конверсию). Если у лида есть Calendly —
     сперва прочитать его слоты сам и предложить реально свободный обоим (канон п.5:
     ±30 мин, оба календаря, время в двух поясах). Draft-first.
   - **Молчит на касание с CTA** → допинг по лестнице (канон п.3–4): следующее касание
     через 1–2 дня с НОВЫМ углом/пользой, перед ним чистка треда. Не «how are you».
   - **Замолчал ≥3 дней после «да»** → НЕ третий текст (спам). Развернуть на ЖИВОЙ звонок
     Антона: собрать бриф (шаг 5) + отдать Антону «звони, вот повод + номер». Правило
     «звонок, а не текст» — молчание на текст лечится голосом, не ещё-текстом.
   - **Хард-стоп** (деньги/обязательства/секреты) → не автоотправляю, спрос.
5. **Бриф под звонок** (эталон: `_Dashboards/[человек]-Call-Brief.html`, 26.07). Структура:
   повод (его же слова «ты сказал давай») · срез/данные под ЕГО экспертизу (из CRM-Lite/контекста) ·
   3 вопроса, которые задать · как ЗАКРЫТЬ (конкретный ask: ритм/ник/следующий шаг). Голос = Opus.
6. **Лёгкий заход** (если канал = текст): ≤ пары строк, ОБЯЗАТЕЛЬНО с CTA (канон п.2 —
   без CTA не отправляем), один конкретный слот, лёгкий выход («если не до этого — скажи,
   не пропаду»). Крючок из канона п.1: конкретная польза на звонке («принесу срез воронки /
   анализ X»). Отправка только в окно 08:00–23:00 времени Антона (канон п.6). Тон по каналу
   ([[short-text-when-unreviewed]]). Показать Антону → отправка по «+» (advisor-funnel = своя рутина, там авто).
7. **На согласии/брони:** `outreach_log.py register --status call-booked` + создать календарь-hold +
   положить пре-колл-бриф; **поставить no-show-протекцию (канон п.10)**; в бриф вписать DoD
   (канон п.11): забрать TG/WhatsApp + забукать следующий звонок в конце текущего.
   Сам пре-колл-бриф (кто это · чего хочет · как вести) собирает `/call-prep` — бронь → ключи → волт.
   Connect: «доведено» = звонок В КАЛЕНДАРЕ, не «написал».

   ⚙️ **Механизм п.10 (построен 10.08 по голосовой hub:5225 — раньше правило было без движка):**
   - Забукал или нет — не гадаем, СМОТРИМ: Calendly MCP `meetings-list_events` +

   - Паспорт движка: `~/.claude/scripts/docs/call-reminders.md`.

## Границы
- Я НЕ звоню (не умею) — звонок делает Антон; моё = довести до момента «взять трубку» без трения.
- Отправка текста лиду и бронь = по «+» Антона (кроме advisor-funnel-рутины).
- Один лид за раз глубоко > десять поверхностно ([[proactive-lead-copilot]] объём→глубина).
