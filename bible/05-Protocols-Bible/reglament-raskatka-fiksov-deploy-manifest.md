# Раскатка фиксов — распаковывай посылки НЕМЕДЛЕННО + деплой-манифест

> Правило Антона (origin: anton, эмфатично 2026-07-06: «распаковывай все посылки/апдейты НЕМЕДЛЕННО после получения!!!»). Для всех акторов на всех машинах. Родитель — `one-system-propagate [internal]` и правило Connect `connect-rule-pipeline-ownership [internal]`; рельс доставки — `[[reglament-multi-machine-claude-i-peredacha-mezhdu-mashinami]]`.

## 0. Повод (доказательство, зачем правило)
06.07 Антон заметил: фикс «чёрные окна» (S4U-flip задач) дошёл до ноута по синку ещё 05.07, но **никто не применил** его до 06.07 — сидел мёртвым грузом. Аудит доставок ноута нашёл ещё и **полу-применённую** посылку `memory-guard` (скрипт+одна задача заведены, вторая — `Memory Index Tidy` — нет). Класс проблемы: доставки, требующие установочного шага, тихо оседают неприменёнными.

## 1. Корень (почему у хаба «случилось», а у пира нет)
- **Хаб «собрал = применил» в одной сессии** — горячий контекст, админ уже дан.
- **Пир только ПАССИВНО получает** артефакт по Syncthing. Применение требует **активного шага** (копия на место / завести задачу / клик UAC / запуск установщика).
- **Всплывает на входе только always-loaded контент** (CLAUDE.md, MEMORY.md, память, Библия через grep/RAG). Код/задачи/хуки/установщики всплывающей поверхности не имеют → невидимы → забыты или применены наполовину.
- Итог: `one-system-propagate`/Connect заданы как **принципы без механизма-исполнителя** для деплой-класса.

## 2. Закон (must, origin: anton)
**Синк доставил ≠ применено. Лежащая посылка = невыполненный фикс, а не «готово».**
1. **Распаковываю НЕМЕДЛЕННО.** Обнаружил прилетевшую посылку/апдейт/фикс (в `_transit`/`_deploy`/инбоксе/шине), которой нужен установочный шаг — применяю СРАЗУ, не откладываю «на потом». На старте каждой сессии и при любом заходе в шину/`_transit` — проверяю «есть ли непринятые посылки для ЭТОЙ машины?».
2. **До конца, не наполовину.** Применить → прогнать `verify` → отметить `DONE-<host>/<id>.ok` → ACK в шину. Часть задач заведена, часть нет = НЕ готово.
3. **Регистрирую при отправке.** Собрал фикс, которому у пиров нужен установочный шаг → пишу строку в манифест `[шина]/_deploy/PENDING-<ЦЕЛЕВОЙ-HOSTNAME>.jsonl` (`{id, title, apply, verify, sent}`). Без манифеста доставка невидима принимающему.

## 3. Границы
- Установочный шаг с **UAC / деньгами / необратимым / выдачей секрета** = всё равно **Tier-2**: спрос перед применением (голосом рядом или `QQQ` в чат). Но «Tier-2» ≠ «отложить и забыть» — применяю сразу, как получу ОК; висящее ставлю в доску, не роняю.
- Канон-файлы (CLAUDE.md/Библия/standing-память) коммитит вожак-хаб `machine-governance-leader-follower [internal]`; пир предлагает через `_transit/canon-proposals`. Сам ФИКС (скрипт/задача/хук) пир применяет у себя автономно — это локальное, не канон.
- Координация перед правкой sensitive-файла остаётся `[[reglament-koordinatsiya-sessiy-pered-pravkoy-sensitive-failov]]`.

## 4. Механизм-исполнитель (AK-47, закрывает класс)
Три маленьких куска, переиспользуют `_deploy` + паттерн `inbox_hook`:
- `deploy_register.py <target> <id> <title> <apply> <verify>` — строка в `PENDING-<target>.jsonl` (отправитель).
- `deploy_check.cmd` → SessionStart-хук на каждой машине: печатает висящие для своего hostname (0 токенов, только при N>0). Делает посылки невидимо-непропускаемыми.
- `deploy_apply.py <id>` — гоняет `verify`, пишет `DONE-<host>/<id>.ok` + ACK в шину; хаб видит по флоту кто что раскатал.

⚠️ УСЛОЖНЕНИЕ: +1 SessionStart-хук. Лечит тихо-теряемые/полуприменённые фиксы (доказано ≥3 случая 06.07). Дешёвая альтернатива — ручной скилл `/deploy-check`, но тогда снова «надо вспомнить» → корень не закрыт. Постройка ждёт «+» Антона.
