# Файл «не нашёлся» → сначала проверить, НЕ пересоздавать

**Правило (Антон, 2026-06-21, must).** Когда нужный файл/заметка/реглумент **«не находится»** — это **НЕ значит, что его нет**. Прежде чем создавать его заново — **остановиться и проверить**. Пересоздать существующий файл = сделать **дубль** или **затереть настоящий**, когда он появится.

**WHEN** поиск вернул пусто / «файл не найден» / заметка вроде бы отсутствует
**→ DO** НЕ пересоздавать сразу. Сначала проверить три невинные причины «пропажи»:
1. **Искали не там** — у нас данные на разных дисках/папках (знания на `[путь владельца]`, конфиг/скрипты на `C:`). Проверить другой диск/путь.
2. **Файл ещё едет по синхронизации (Syncthing)** — создан на ДРУГОЙ машине и доезжает на эту ~10 секунд по локальной сети; если та машина выключена или вне сети — ждёт дольше. Дать синку мгновение / глянуть машину-источник.
3. **Лежит под другим именем/путём, или в бэкапе** — проверить git / бэкап / папку оригиналов `_originals` / алиасы.

**Только если все проверки пусты** — тогда создавать (и то аккуратно, чтобы не задвоить).

**Зачем:** «не вижу» ≠ «нет». Пересоздание поверх настоящего рушит данные тихо: появляется второй файл-дубль, либо при доезде синка твоя свежая пустышка затирает реальное содержимое. Один лишний взгляд дешевле потери данных.

**Пример (поймано 2026-06-21):** поиск «не нашёл» реглумент Библии. Сначала заподозрили лаг Syncthing (файл создан на десктопе и ещё не доехал). На деле это был баг поиска — искали на диске `C:`, а волт на `E:`. Реглумент был на месте всё это время, лага не было. Если бы пересоздали — получили бы дубль.

**Применяется к:** ассистенты (живые) + AI-агенты.
**Машинный слой (для AI):** память `deterministic-script-gotchas` (грабли [путь владельца] + «не пересоздавать ненайденное») + `CLAUDE.md` §«два хранилища — волт на E:, конфиг на C:».
