# 🏛️ Регламент — нервная система машин всегда без LLM; тупой детектор первым

> Кросс-акторное правило (для Антона, живых ассистентов И кремниевых агентов — я/Codex/любой LLM). Машина-канон: память llm-free-transport-dumb-detector-first [internal] + след в `CLAUDE.md`/`MEMORY.md`. Решение: [[decision-dumb-detector-first-llm-free-transport-2026-06-26]]. Связано: vault-data-architecture [internal] (дешёвый инструмент первым), fix-root-cause-not-symptoms [internal], verify-existing-before-proposing [internal], system-architect [internal].

## Зачем (грабли 2026-06-26)
Компьютер [коллега] доложил «твой хаб оффлайн, inbox не работает». Антон испугался: «Опус умер → всё накрылось; давайте, чтобы слушалки работали на Sonnet или на in-house LLM». Разбор логов показал **ДВЕ разные болезни**, ошибочно слитые в одну:
1. То, что видел пир («хаб оффлайн») = **Syncthing-отвал** пира (транспорт файлов), к LLM отношения ноль.
2. Реальный лимит LLM был, но робот **уже на Sonnet**, и сбой **молчал в лог-файл** — никто не узнавал.

Корневая ошибка-предпосылка: будто нужна **«всегда включённая LLM-слушалка»**. Её нет и не должно. `claude -p` — не демон: дёрнули → отработал ~30с → выключился. Настоящая «слушалка всего» = **планировщик ОС + детерминированный Python**, всегда живой, бесплатный, без лимитов.

## Правило (must)
1. **Детекция ≠ мышление. Разделяй слои:**
   - **Будильник** (крон каждые N мин) = планировщик ОС. **0 LLM.**
   - **Детектор** (есть ли новое: инбокс/шина/почта/телега) = чистый код (API/Telethon/файлы). **0 LLM.** «Принести конверт» — не мышление.
   - **Думалка** (что с этим делать) = LLM, вызывается **по требованию**, только когда детектор что-то нашёл.
2. **Транспорт/пинги/relay/liveness НИКОГДА не вешать на LLM** — ни Opus, ни Sonnet (даже бесплатный Sonnet иногда упирается в недельный лимит). Relay сообщения между машинами = `скопировать файл` / `послать телеграм` = код. Локальная LLM транспорту НЕ нужна.
3. **Тупой детектор ПЕРВЫМ.** Крон → сперва бесплатный 0-токенный детектор. Пусто → выход, LLM не зовём (бережём бак, ~95% циклов пусты). Есть пункт → **только тогда** зовём LLM. Это и надёжнее, и само снижает риск упора в лимит.
4. **Сбой = ГРОМКО, не молча.** LLM в лимите/ошибке → детерминированно (без LLM) детектить «упёрся» (строки/exit-код) и **пинговать человека** («думать нечем, но машина жива»), на восстановлении — «снова в строю». Молчание в лог-файл = запрещено.
5. **Детекция переживает обвал LLM.** Если думалка легла, а пункт есть — детектор всё равно **зафиксировал** его (паркует/алертит), не потеряет; обработка — когда модель вернётся. **Fail-open:** детектор не уверен → будит LLM (лучше зря разбудить, чем пропустить).
6. **Локальная in-house LLM** (если когда-то ставим) = резерв **только для ДУМАЮЩИХ** рутин при полном обвале облака, НЕ для транспорта; на скромном железе — только грубый «отнеси-подай-классифицируй», и **никогда** для авторского голоса Антона (тот = только Opus).

## Тест перед тем как вешать что-то на LLM
«Это **детекция/транспорт** (принести/передать/проверить-есть-ли) или **мышление** (решить/написать/классифицировать)?» Детекция → код, 0 LLM, всегда-вкл. Мышление → LLM по требованию. Если поймал себя на «надо, чтобы модель всегда работала, иначе слушалка умрёт» — **архитектура неверна**, перенеси слушалку на ОС+Python.

## Эталон-реализация (хаб, 2026-06-26)
- Слушалка кросс-машинного inbox = планировщик Windows (~20 мин) + `~/.claude/scripts/inbox_robot.cmd`.
- Тупые детекторы (0 LLM): `machine_bus.py robot-scan` (файл-рельс) + `bus_tg_peek.py check` (телега-рельс, сессия `@[рабочий аккаунт]`+лок, fail-open). Обе пусты → `claude -p` НЕ вызывается.
- Громкий алерт: `robot_alert_guard.py` (🔴 лимит/ошибка → Telegram через `bus_ping.py`; 🟢 восстановление; коммит offset только при чистом прогоне).
- Liveness пиров: `sync_monitor.py` (чистый Python, пингует при отвале) — тоже 0 LLM.
