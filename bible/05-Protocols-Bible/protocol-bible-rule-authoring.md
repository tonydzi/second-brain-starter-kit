# Как писать новое правило в Библию — плейбук

> Контракт высот, `audience` и конфликтов — [[protocol-bible-as-prompt]]. Это его детальная, пошаговая часть «как именно написать одно правило». Атомарное правило-семя от Антона на ту же тему — [[reglament-lyuboe-pravilo-v-bibliyu-pisat-maksimalno-doslovno-so-s]].

**Когда применять:** каждый раз, когда ты (агент/LLM) или человек собирается добавить, изменить или отменить правило в Библии.
**Цель на выходе:** готовая нота правила, которую через год поймёт любой читатель — человек ИЛИ слабая LLM, без «ну ты понял».

**Золотое правило (если запомнишь только одно):**
> Правило = **КОГДА `<ситуация>` → ДЕЛАЙ `<действие>`** — дословно, с примером, в нужной папке, с честным авторством, без дублей и без секретов.

---

## Шаг 0. Это вообще правило? (триггер)
Пиши правило, только если есть ОДНО из:
- **Антон продиктовал** правило или решил «так теперь всегда».
- **Грабли:** случилась ошибка, которая может повториться → сразу пиши правило, чтобы защитить команду ([[reglament-svoevremenno-propisyvat-pravila-biblii-i-ustranyat-uzhe]]).
- **Классная связка:** нашли удобный повторяемый приём — закрепляем.

❌ Разовый случай «на один раз» — НЕ правило, не засоряй свод.

🔎 **ДО → ПОСЛЕ:**
- ДО (плохо, разовое): «Сегодня отправили Денису адрес пиццерии».
- ПОСЛЕ (правило, повторяемое): «КОГДА отправляем кому-то адрес встречи → шлём геолокацию-пином, не текстом».

## Шаг 1. RECALL — а такого правила ещё нет? (обязательно)
Дубли = свод разъезжается. Прежде чем писать — проверь:
1. `grep` по `03-Insights\Operations\reglament-*` и `05-Resources\Protocols\protocol-*`.
2. Смысл: `python [путь владельца] "<суть правила>"`.
3. Нашлось похожее?
   - **То же самое** → не плоди копию, обнови существующее.
   - **Противоречит / уточняет** → иди в Шаг 6 (отмена/supersede).
   - **Ничего нет** → пиши новое.

## Шаг 2. Это правило Библии — или про то, как работает Claude? (один вопрос-маршрут)
Задай себе ОДИН вопрос: **правило управляет действиями ОТ ЛИЦА Антона с ЛЮДЬМИ / наружу?** (аутрич, ответы в его чатах, ассистенты, закупки, найм, календарь, быт)
- **ДА** → это Библия, продолжай здесь (`reglament-*` в волте).
- **НЕТ, это про то, как работаю Я (Claude) как инструмент** (формат ответа, какие скрипты гонять, привычки сессии) → СТОП, это не Библия. Дом — `CLAUDE.md` / skill / memory / hook (см. правило памяти Claude `operating-agreement` → «Where durable rules go»).

Не клади машинные правила в Библию и наоборот. Каждый уровень ссылается, не дублирует.

## Шаг 3. Высота и тема
**Высота** (что именно пишешь):
- `reglament-*` — атомарное дословное правило. **← по умолчанию, ~90% случаев.**
- `protocol-*` — многошаговый плейбук (скрипт звонка, воронка).
- `insight-*` — принцип/дух («сказал Антон — делаем»).
- `decision-*` — точечный прецедент (что решили и почему).

**Тема/ветка** задаёт папку и ссылку `concept:`:
`communications` · `staff-hr` · `procurement` · `travel` · `finance` · `child-education` · `household` · `access-security` · `social-media` · `outreach` (приоритет #1) → концепт `concept-bible-<тема> [internal]`.

## Шаг 4. Текст правила (сердце)
Пиши так, чтобы понял любой человек И слабая LLM после тебя:
- **Дословно** со слов Антона (диктовал — цитируй, не пересказывай).
- **Императив + триггер:** «**КОГДА** `<условие>` → **ДЕЛАЙ** `<действие>`».
- **Самодостаточно** — без «ты понял о чём я», без местоимений без имён.
- **+ Пример** прямо в правиле.

🔎 **ДО → ПОСЛЕ (на реальном правиле календаря):**
- ДО (расплывчато): «Заполнять календарь правильно».
- ПОСЛЕ (готово): «КОГДА ставим событие Антону в Google Calendar → название по стандарту, время строго по локальному часовому поясу события, в конце — автор события. Пример: “Урок [коллега] — гитара (ставила Оксана)”.»

## Шаг 5. Frontmatter (паспорт правила)
Возьми шаблон ниже. Что значит каждое поле:
- `type` — высота (`reglament` / `protocol` / …).
- `origin` — ЧЕЙ голос: `anton` (Антон сам) · `mixed` (Антон+команда) · `external` (извне). **Честно.**
- `authored_by` — кто оформил: `human` / `hybrid` / `claude`.
- ⚠️ Автор не Антон? → `origin` = настоящий автор, и **НИКОГДА** не вешай `anton` / `#anton-original` на чужое (правило памяти Claude `provenance-attribute-real-author`: «не вешай на меня то, что Я НЕ ПИСАЛ»).
- `date_established` — дата (сегодня); по ней решаются конфликты.
- `theme`, `applies_to` — тема и к кому («ассистенты» / «агент» / «все»).
- `audience` — `human` (нужно живое суждение) · `agent` (машинно-исполнимо) · `both` (обычно).
- `status: active` · `confidence` — насколько уверены (0–1).
- `concept: "concept-bible-<тема> [internal]"` — ссылка на ветку.

## Шаг 6. Конфликт: новое отменяет старое?
- **Свежее бьёт старое по той же теме** (закон Антона). В НОВОЕ добавь `supersedes: "старое [internal]"`; в СТАРОЕ — `status: superseded` + `superseded_by: "новое [internal]"`.
- **Защита правил Антона:** правило с `origin: anton` нельзя перебить просто датой — только новым правилом Антона ИЛИ явным `supersedes`. Хочешь (как агент) изменить правило Антона — не молча, а **эскалируй Антону**.
- Старое НЕ удаляй по маске — помечай `superseded`, не стирай (правило памяти Claude `vault-backup-rule`: никогда не удалять по маске, бэкап перед записью).

## Шаг 7. Секреты — НЕ внутрь
В загружаемое правило не клади пароли, доступы, финцифры, «серые» техники: Библия = промпт для агентов → это канал утечки. Секреты живут отдельно ([[decision-bible-secrets-quarantine]]).

## Шаг 8. Сохрани правильно
1. **Бэкап до записи:** `python [путь владельца]` (волт — git-репо; правило памяти Claude `vault-backup-rule`).
2. Создай ноту в правильной папке (Шаг 3). Имя: `reglament-<слаг-из-сути>.md`.
3. **Свяжи:** короткий вики-линк из ветки/MOC (`concept-bible-<тема> [internal]`, `[[MOC-holy-bible]]`), чтобы нота не висела сиротой.
4. **Реиндекс:** `python [путь владельца]` — чтобы поиск её нашёл (правило памяти Claude `reindex-routine`).

## Шаг 9. Самопроверка + согласование
Перечитай по чек-листу: КОГДА→ДЕЛАЙ? пример есть? дублей нет? авторство честное? секретов нет? папка/ссылка верные?
- **Антон сам продиктовал** → пиши дословно и покажи готовое («записал так — верно?»).
- **Ты (агент) сам вывел правило** → НЕ пиши молча в живой волт. Покажи **ДО→ПОСЛЕ на его реальных данных** и получи «да» (Tier-2; правила памяти Claude `operating-agreement`, `show-before-after`). Только после «да» — в волт.

## ✅ Полный пример (от идеи до готовой ноты)
**Ситуация:** Антон голосом: «Когда букнули лиду звонок, а он не пришёл — пингуем в тот же день, не на следующий».
1. **Триггер:** Антон продиктовал, повторяемое → правило (Шаг 0 ✔).
2. **RECALL:** `brain_ask.py "пинг лида под сдачу звонка"` → есть похожее `reglament-kazhdyy-raz-kogda-nuzhno-pinganut-lida...` → **уточняет его** → Шаг 6.
3. **Маршрут:** действие с лидом наружу → Библия ✔. Тема: `outreach`.
4. **Высота:** `reglament`.
5. **Текст:** «КОГДА забукали лиду звонок и он не явился → пингуем В ТОТ ЖЕ день, не на следующий. Пример: звонок в 15:00 не состоялся — пишем до конца дня».
6. **Конфликт:** в новое `supersedes: "reglament-kazhdyy-raz-kogda-nuzhno-pinganut-lida... [internal]"`, старому — `superseded_by`.
7. **Секретов нет** ✔.
8. **Бэкап** → создаю `reglament-ping-lida-v-tot-zhe-den.md` в `03-Insights\Operations\` → линк из `_Bible-Outreach-MOC` → реиндекс.
9. **Самопроверка** ✔ → показываю Антону ДО→ПОСЛЕ → «да» → сохраняю.

## ❌ Антипаттерны (так НЕ делать)
- Дубль вместо обновления существующего (пропущен Шаг 1).
- Расплывчато: «делать хорошо», «как обычно», «ты понял».
- Чужой текст с `origin: anton` (правило памяти Claude `provenance-attribute-real-author`).
- Машинное правило (как работает Claude) засунули в Библию (Шаг 2).
- Секреты внутри загружаемого правила (Шаг 7).
- Удаление/правка старого по маске вместо `superseded` (Шаг 6).
- Агент молча записал в живой волт без согласования (Шаг 9).
