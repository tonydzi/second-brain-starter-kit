**Правило (WHEN → DO):** НИКАКАЯ фоновая / автономная / запланированная задача, которая может **зависнуть** (headless `claude -p`, любой долгий вызов модели/процесса, импорт, синк, скрейпер, сетевой вызов), НЕ запускается «выстрелил-и-забыл». Каждая обязана иметь **(1) жёсткий таймаут по стене** и **(2) убийство ВСЕГО дерева процессов при таймауте** (`taskkill /F /T` на Windows), плюс возврат явного кода ошибки (124), чтобы сторож/пинг сработал.

**Зачем (что ломается без этого):** зависший headless-агент (стук модели, лимит API, застрявший инструмент, сеть) висит **ВЕЧНО** — крон никогда не возвращается, exit-строка и guard не выполняются, машина **выглядит живой, но заморожена**. Хуже: при периодическом запуске (каждые N минут) зависшие экземпляры **КОПЯТСЯ зомби-процессами** → давят RAM (видели хвост 31 × `claude.exe`, до 850 МБ каждый, с прошлой ночи) → подвешивают других роботов. Это тихий сбой (self-debug-transparency [internal]): пустой/«живой» статус ≠ всё работает.

**Как применять (AK-47):**
- **Обёртка-жнец:** headless `claude -p` (и любой долгий unattended-вызов) идёт ТОЛЬКО через `claude_run.py <таймаут_сек> -- <команда>` — она убивает всё дерево на таймауте и чисто возвращает код. Промпт из файла через stdin → флаг `--stdin <файл>` (не теряется).
- **Таймаут по работе, не «на глаз вечно»:** лёгкий Sonnet-крон ~300с; тяжёлая Opus-уборка ~900с. Подбирать под модель/объём, но КОНЕЧНЫМ числом.
- **Чинить КЛАСС, не экземпляр (fix-root-cause-not-symptoms [internal]):** обернул одну крон-задачу — проверь и оберни ВСЕ однотипные (`grep "claude -p"` без `claude_run`). Один защищённый робот при десятке голых = ложное чувство безопасности.
- **Belt-and-suspenders:** периодический детерминированный health-guard, замечающий накопление (например, «N+ `claude.exe` старше X часов») и пингующий в ТГ-шину (machine-bus-telegram-rail [internal]).
- **Пропагировать на ВСЕ машины (one-system-propagate [internal]):** движок-обёртка в синкаемом `~/.claude/scripts`, правка крон-обёрток едет на все узлы; фикс «не готов, пока не разложен везде и не проверен».
- **Тест перед «готово» (test-after-build-skill [internal]):** доказать обёртку тремя прогонами — happy-path (rc=0), таймаут (rc=124, дерево убито), `--stdin` (промпт доехал).

**Пример (ДО → ПОСЛЕ) на реальных задачах Антона (2026-06-27):**
- **ДО:** `inbox-robot` крутился каждые 15 мин БЕЗ таймаута → каждый зависший на лимите API экземпляр оставался жить и копился (хвост с прошлой ночи). Ещё 3 задачи (`alpha/judge_nightly`, `chatgpt_freshness_check`, `memory_tidy`) звали `claude -p` напрямую, без жнеца.
- **ПОСЛЕ:** `inbox-robot` обёрнут в `claude_run.py 300` (сделано раньше); все 3 оставшиеся обёрнуты — judge 300с, freshness 300с (`--stdin nag_prompt.txt`), memory_tidy 900с (Opus). Зомби больше не плодятся; зависший прогон убивается за лимит и пингует.

**Применяется к:** Claude Code (главный исполнитель) + любой ассистент/агент, который ставит фоновые/запланированные задачи Антона.
