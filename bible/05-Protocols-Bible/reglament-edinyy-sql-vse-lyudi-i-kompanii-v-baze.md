**Правило:** Абсолютно ВСЕ люди и абсолютно ВСЕ компании, которые есть в волте (из любого импорта, любого источника), обязаны быть в едином SQL (`leads.db`). Никакого зоопарка и разнобоя — один источник правды для сущностей.

## Структура

Три главных массива, полностью перелинкованные:

1. **Компании** (таблица `companies`) — каждая компания из волта, без дублей
2. **Люди** (таблица `people`) — каждый человек из волта, без дублей
3. **Раунды** (таблица `vc_round` + вью) — инвестиционные раунды

## Вложенность (cross-links)

Каждая сущность содержит вложенные массивы связанных сущностей:

- **Внутри компании:** люди (сотрудники/основатели) + раунды (поднятые/полученные инвестиции)
- **Внутри человека:** компании (где работает/работал) + раунды (куда инвестировал)
- **Внутри раунда:** компания (стартап) + инвесторы (люди и фонды)

Связи реализуются через junction-таблицы: `works_at` (человек↔компания), `company_round` / `person_round` (через вью над vc_* таблицами).

## Обязательства при импорте

Каждый новый импорт (Telegram, CRM, Apple Contacts, VC-данные, любой другой) **обязан завершаться** шагом: «довнести новых людей/компании в единые таблицы + проставить связи». Импорт без этого шага = незавершённый импорт.

## Дедупликация

- Компании: по нормализованному ключу (транслитерация + lowercase + strip legal suffixes)
- Люди: по tg_id (сильный), по handle (средний), по имя+компания (осторожный)
- Дубли = грязные данные = нарушение правила

**Применяется к:** все акторы (AI + ассистенты) — любой, кто пишет данные в волт
