**Правило (WHEN → DO):** Когда подаёшь Антону **аудит висячих / открытых / недоделанных задач** (открытые пункты, блокеры, «что не закрыто», «что зависло», бэклог, незавершённые обязательства) — результат **ВСЕГДА оформляется как ВИЗУАЛЬНЫЙ ДАШБОРД** (самодостаточный HTML в `_Dashboards\`), а не только текстовой стеной в чат. Правило Антона, дословно: «да ВСЕГДА ДЕЛАЙ ДАШБОРД по таким ВИСЯЧИМ ЗАДАЧАМ».

**Зачем:** Антон — не-технарь, работает глазами, а не командной строкой ([[reglament-otchet-antonu-vizualno-dashboard-ne-stena-cli|визуальный дашборд по умолчанию]]). Список из десятков висячих задач в виде текста — нечитаем и теряется; дашборд с группировкой, приоритетами и галочками — это живая доска, по которой видно одним взглядом: что висит, кто должен действовать, что уже закрыто.

**Как делать (АК-47 — один HTML-файл, без зависимостей, Антон сам откроет и поймёт):**
- **Дом:** `[путь владельца]` (рядом с остальными; стиль-палитра единая — переиспользуй существующий дашборд как образец, не изобретай вид).
- **Группировка по ВЛАДЕЛЬЦУ действия** (главное для Антона — что от НЕГО): 🔴 ждут лично Антона · 🟡 на мне (Claude) · ⏳ ждёт другие машины / внешнее · ✅ закрыто. Внутри — по приоритету (hi/med/low).
- **Каждая задача:** короткий заголовок · что именно нужно сделать · источник (какая заметка/ретро/решение). Приоритет — цветным тегом.
- **Живая доска, не картинка:** галочки «сделано» с запоминанием (localStorage), фильтр по владельцу, счётчики сверху. Чтобы Антон реально отмечал прогресс.
- **Обязательная пара — RECALL перед подачей:** по КАЖДОЙ висячей задаче сперва проверить «не сделано ли уже» (live scheduled-tasks · свежие ретро · текущее состояние памяти), и в дашборде отдельной секцией показать «✅ закрыто по факту» — не верить памяти на слово (verify-existing-before-proposing [internal], self-debug-transparency [internal]).
- **Бэкап перед записью** в волт (vault-backup-rule [internal]); дашборд — НОВЫЙ файл, не перезаписывай чужой.

**Пример (ДО → ПОСЛЕ) на реальной задаче Антона (2026-06-26):** ДО — на запрос «найди блокеры и забытые задачи» выдал ~47 висячих пунктов **текстовой стеной** в чат (читается тяжело, теряется к следующей сессии). ПОСЛЕ — те же пункты собраны в `Hanging-Tasks-Dashboard.html`: 3 цветных группы по владельцу + секция «закрыто по recall», кликабельные счётчики-фильтры, галочки с памятью. Антон открывает файл и одним взглядом видит «10 на мне как на хозяине, жму галочки по мере закрытия».

**Граница:** правило про подачу АУДИТА висячих задач. Разовый вопрос «а что с задачей X?» (одна-две) — дашборд не нужен, отвечай текстом. Дашборд включается, когда пунктов МНОГО и это именно обзор бэклога/открытых пунктов.

**Применяется к:** Claude Code (главный исполнитель) + любой ассистент/агент, который сводит Антону список незакрытых дел.
