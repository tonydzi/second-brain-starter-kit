# Реглумент — дрифт от главной цели: сорняки в соседние сессии, не в эту

> Правило Антона (origin: anton, 2026-07-03): «У нас есть главная задача. По пути возникает куча отвлекающих: что-то сломалось, 150 других вещей. Нас сносит ветром от цели. Если сильно снесло — не пытайся всё чинить сама в этой же сессии, получается помойка. Скажи: "Антон, вот тебе seed-промпты для других сессий, запусти их". И по правилу Connect — мониторь: я запускал сессии по твоим сидам, докладывай, чего они добились и помогло ли это главной цели.»

У сессии есть **главная цель** (то, ради чего сели). По пути всплывают сорняки: сломанный скрипт, упавшая рутина, битая ссылка, зомби-процесс. Каждый сорняк по отдельности полезен, но чиня их подряд в одной сессии, мы (а) теряем главную нить, (б) захламляем контекст, (в) в конце «делали много, главное не сделали».

## Триггер (когда срабатывает)
Я замечаю **дрифт**: главная задача сессии стоит, а мы уже N-ную по счёту побочную вещь чиним/копаем, или очередной сорняк тянет за собой ещё работу. Признаки: третье подряд «а ещё сломалось…»; починка сорняка требует своего RECALL/отладки/установки; контекст сессии уже наполовину не про главную цель.

## Поведение (развилка по размеру сорняка)
1. **Мелочь ≤ пары минут, обратимая, по пути** → чиню сам молча, не считается дрифтом ([[reglament-uvidel-polomku-vsegda-predlozhi-pochinit]] ветка «а»).
2. **Блокирует главную задачу** (без этого главную не сделать) → чиню здесь: это не сорняк, это часть пути.
3. **Всё остальное (не блокирует, но тянет время/контекст)** → НЕ чиню здесь. Выдаю Антону **seed-промпт для соседней сессии** (paste-ready, самодостаточный: Outcome · Контекст из recall · Scope · Deliverable · DoD — формат из [[reglament-dekompozitsiya-zadachi-na-parallelnye-sessii]]) и возвращаюсь к главной цели одной фразой: «⛳ возвращаемся к <главная цель>». Механика в Claude Code (chip-first, обновлено 2026-07-04): дефолт — **spawn_task-чип** (кнопка `mcp__ccd_session__spawn_task`: Антон жмёт один раз → сорняк уходит в свою новую сессию с самодостаточным промптом; лучший для Антона, GUI без CLI). Fallback, когда инструмент недоступен (голый CLI) — текст seed-промпта в чат + подсказка `/bg <seed>` / `claude --bg`. Новая сессия стартует холодной → промпт чипа обязан быть самодостаточным. Только настоящий сорняк = чип, не каждая побочная мысль (не спамить кнопками). Потолок одновременных вынесенных сессий (~3 пишущих + 2 ревью), расширенные поля сида (владеемые файлы · не-цели · команды проверки · принятые решения · эскалация) и тест на спавн из 5 условий — в сестре [[reglament-dekompozitsiya-zadachi-na-parallelnye-sessii]] (усилено DR26-07-04-HUB-10).

## Connect — выдал сид ≠ закрыл тему
По правилу Connect ([[reglament-pravilo-connect-esafeta-otvetstvennosti]]) передача сорняка в соседнюю сессию — это эстафета, я владею результатом:
- каждый выданный seed **регистрирую в durable-бэклоге** (`task_registry.py` — не теряется между сессиями);
- в seed всегда есть **Deliverable-локация** → результат проверяем детерминированно (файл есть/нет, счётчик), не «на слово»;
- при следующем чекине (`?` от Антона, новая сессия по теме, /retro, аудит висячих) **докладываю карту**: «выдал сиды A, B, C → A сделала X (помогло главной цели тем-то), B молчит (перевыдать?), C не добилась»;
- молчание сессии ≠ выполнено; повисший сид → в hanging-tasks-dashboard [internal].

## Зачем (корень)
Одна сессия = один контекст = одна главная линия. Сорняки в той же сессии = помойка: контекст размывается, главная цель тонет, в ретро нечего предъявить. Соседние сессии дают каждому сорняку свой чистый контекст, а главной линии — фокус. Это **фокус-гигиена**, сестра декомпозиции: [[reglament-dekompozitsiya-zadachi-na-parallelnye-sessii]] дробит ОДНУ большую задачу заранее; этот регламент выгружает ЧУЖИЕ задачи-сорняки по ходу.

## Для живого ассистента (тот же принцип без LLM)
Делаешь главную задачу дня, всплывают побочные просьбы/поломки — не бросай главную и не чини всё подряд. Мелочь по пути — сделай; остальное запиши отдельной задачей с чётким брифом (что·зачем·куда результат) и отдай в отдельный поток (другой день/человек/слот), а сам вернись к главной. Отданное отслеживай до результата, не до «передал».

## Границы
- Не превращать в отговорку: «выгрузил в сид» ≠ «можно забыть» — Connect-мониторинг обязателен.
- Критичная поломка (данные теряются, безопасность, синк лёг) — чиню/эскалирую сразу, дрифт-правило не откладывает пожары.
- Tier-2 внутри соседних сессий — те же хард-стопы.
