# Регламент — слияние общих сторов: UNION по содержимому, не по дате

> **Для кого:** для ВСЕХ акторов (Антон + живые ассистенты + AI-агенты). Любой, кто сводит две копии общего хранилища.
> **Откуда правило:** реальный инцидент 2026-06-22 — при синхронизации общего стора секретов между двумя машинами авто-слияние по времени отдало победу более СВЕЖЕЙ, но более КОРОТКОЙ копии, и она ТИХО выбросила: доступ по SSH к боевому серверу (полный root!), ключ API и детальные пароли 2FA по аккаунтам. Поймали вручную, склеили по содержимому, вернули. Без этого правила потеряли бы доступ к боевой инфраструктуре.

## Когда применяется (триггер)
Каждый раз, когда надо СВЕСТИ две копии ОБЩЕГО ХРАНИЛИЩА, в котором записи НАКАПЛИВАЮТСЯ: стор паролей/доступов, список контактов/лидов, реестр, журнал, любой «лист, куда дописывают». Особенно — когда:
- инструмент синка (Syncthing / Dropbox / Google Drive) создал файл `*.sync-conflict-*`;
- два человека (или человек и агент) правили одну и ту же запись на разных машинах;
- один файл «победил» автоматически, и его размер МЕНЬШЕ другого.

## Правило (по шагам)
1. **НИКОГДА не решай по времени / «свежее побеждает» / авто-мёрджу.** Более новая копия может быть КОРОЧЕ и молча потерять записи. «Свежее» = тай-брейк для ОДНОЙ записи, НЕ команда «взять весь короткий файл».
2. **Сперва БЭКАП обеих версий** — копия с датой ВНЕ синкаемой папки (чтобы синк её не перезаписал). Это страховка: даже если ошибёшься в слиянии, ничего не потеряно.
3. **Сливай UNION-ом по СОДЕРЖИМОМУ:** сохрани КАЖДУЮ запись, что есть хотя бы в одной копии. «Свежее побеждает» применяй ТОЛЬКО к настоящему конфликту одной записи (тот же сервис/поле, разное значение). Если проигравшая запись — это ДОСТУП/пароль, сохрани и её (хотя бы заметкой).
4. **ПРОВЕРЬ, что ничего не выпало:** сравни число записей + явно посмотри критичные (доступы к серверам, деньги, необратимое). Результат КОРОЧЕ самого длинного входа = красный флаг, разбирайся.
5. **`*.sync-conflict-*` файлы = «обязательно слить вручную»**, а НЕ «удалить конфликт и забыть». Удаляй конфликт-файл ТОЛЬКО после того, как его содержимое влито в union.
6. **Максимальная осторожность для СЕКРЕТОВ/ДОСТУПОВ:** потеря одного пароля = потеря доступа к живой инфраструктуре. Слияние стора секретов = Tier-2 (бэкап + проверка + при сомнении подтверждение Антона). Барьер про утечку неизменен: секрет НИКОГДА в исходящие/публичные/always-loaded.

## Почему так (суть в одной строке)
Синк-инструменты выбирают победителя по версии/времени, а не по полноте. «Новее» ≠ «полнее». Полнота важнее свежести, когда речь о накапливаемом сторе, и критична для доступов.
