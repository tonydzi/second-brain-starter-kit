# 🚪 Протокол «Привратник» (gatekeeper)

> **Зачем (краткая суть, слова Антона):** людей нам нужно много — они «как еда» (топливо лидов). Самый дешёвый и безопасный способ получить право написать человеку в Telegram **без бана** — чтобы человек **сам подал заявку на вступление** в нашу группу. Как только заявка подана — мы можем написать ему в личку сами, без бана, и он даже не может заблокировать заранее. Это «работа привратника» и это **очень важный функционал**.

## Механика (почему это работает)
- В Telegram приватную группу/канал можно настроить так, что вступление идёт **по заявке** (join request / «Подать заявку на вступление»).
- **Заявка человека = его собственное действие-контакт.** Когда наш **аккаунт-админ** (любой аккаунт Антона, обычно **@TonyDzi**) пишет заявителю, Telegram показывает получателю **дружелюбный action-bar «вы недавно просились в {чат}»** — БЕЗ кнопки «Пожаловаться/Заблокировать» (проверено живым UI Антона 2026-06-21; first-source доки `peerSettings`/`action-bar` это не опровергают — про кнопки для заявочного бара молчат). Нет one-tap-репорта → нет жалобной нагрузки → **реально низкий бан**. (Педантично: вручную из профиля заблокировать юзер технически может всегда — но это не та one-tap-жалоба, что банит аккаунты.)
- Поэтому заявка — **анти-бан-ключ через подмену бара**: не мы «холодно ломимся» (враждебный бар с репортом), а человек сам инициировал → дружелюбный бар → мы спокойно пишем. ⚠️ Это свойство ДОКАЗАНО для **user-аккаунта**; наследует ли его бот (через `user_chat_id`) — НЕ подтверждено, поэтому и по [[reglament-telegram-avtomatizatsii-svoy-akkaunt-ne-boty]] делаем это **своим аккаунтом, не ботом**.

## Воронка (WHEN → DO)
1. **Создаём группы, в которые люди хотят вступить.** Типовой случай — Антон ходит по конференциям и делает группы под **сайд-ивенты** вокруг конференции (это делает Антон или его ассистент). Либо просто группа с ценностью, куда люди хотят попасть.
2. **Включаем «вступление по заявке»** (approval required) — без заявки ключ не появляется.
3. **Гоним людей подавать заявку** (промо ивента, инвайт, анонс) — целевое действие = именно **заявка**, а не прямой инвайт.
4. **Привратник пишет вступающему ДО одобрения:** в личку — «расскажи о себе» (так заявитель видит, что мы заметили его заявку; и именно заявка делает это сообщение бан-фри). Вертим/квалифицируем.
5. **Одобряем подходящих / отклоняем спам** (approve / reject заявки).
6. **Теперь можем свободно общаться** со всеми этими людьми → знакомимся **массово, бесплатно, без бана**.

## Границы (это ДОСТУП, не лицензия на спам)
- Сам разговор после открытия ключа всё равно по Библии: **genuine-interest-first**, draft→approve на исходящее ([[reglament-outreach-genuine-interest-first]], Tier-2 `operating-agreement`). Привратник снимает **бан-барьер доступа**, а не правила тона.
- В **элитных крипто-комьюнити** (LobsterDAO, Flashbots, EF) холодного DM всё равно НЕ делаем даже через этот ключ — там zero-cold-DM ([[reglament-elitnye-kripto-komyuniti-zero-cold-dm-value-first]]).
- Спам-заявки **reject**, не одобряем всех подряд.

## Статус реализации + ОТКРЫТЫЙ стратегический вопрос (Антон, 2026-06-21)
- Функционал **уже реализован в CRM** (фича «Gatekeeper», `gatekeeper PM-before-approval` — см. [[crm-know-how-13-patterns]]; в Functional-Map = KEEP). В нашем action-каталоге `lead_actions.py` действия `approve_join` / `reject_join` пока ⚠️ GAP (нет нативного инструмента в нашем Telegram-MCP — нужно добавить, как добавляли `search_dialogs`).
- **Решаем не «копировать ли» (копируем — да), а ГДЕ и КАК использовать:** на **n8n**? на **Claude Code**? или **держим старый CRM-функционал + дописываем новый**? Прогнали по **Alpha Protocol (R+DR)** — 2 Deep Research + проверка first-source. **→ Decision Memo: [[decision-gatekeeper-rebuild-architecture]].**
- **РЕШЕНО (Антон, 2026-06-21):** DM-отправитель = **обычный аккаунт Антона (обычно @TonyDzi), НЕ бот** ([[reglament-telegram-avtomatizatsii-svoy-akkaunt-ne-boty]]) — прозрачно, Антон сам подхватывает диалог, лучше для CRM, и доказанно даёт дружелюбный бар. Идея «делать ботом» (Bot API `user_chat_id`, окно 5 мин) — **отклонена** этим правилом.
- **Архитектура (вердикт D):** оркестратор = **n8n** (видим, без зависимости от ушедшего дева); DM-движок = тонкий задокументированный Telethon-сервис на аккаунтах Антона; **Claude Code = суждение/ветинг/контент**; старый bespoke `core` (aiocron) — отклонить.
