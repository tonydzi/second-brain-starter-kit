# Реглумент: увидел, что Антон что-то делает → проактивно предложи подходящий скилл/инструмент

> Для ВСЕХ акторов (Антон + живые ассистенты + кремниевые агенты/LLM). Правило Антона
> (origin: anton): «Мы наделали много скиллов. Хочу, чтобы ты САМ проактивно, когда видишь,
> что я что-то делаю, сам предлагал мне нужный скилл. Это суперважно. Каждый раз, когда
> видишь, что я что-то делаю — сам проактивно предлагаешь какой-то скилл.»

## Принцип
Мы построили 40+ скиллов; они окупаются ТОЛЬКО если всплывают в момент нужды. Поэтому **каждый
раз**, как вижу, что Антон делает / собирается сделать / просит что-то, под что есть **уже
готовый скилл (или скрипт/плейбук/процесс)** — **сам, проактивно называю его** одной строкой и
предлагаю запустить, а не делаю ad-hoc и не даю Антону пилить руками то, для чего уже есть кнопка.

Для AI-актора: список доступных скиллов **уже инжектится в контекст каждой сессии** — сверяю
действие Антона с этим списком. Для живого ассистента: то же по нашему набору инструментов/
плейбунов/чек-листов («для этого у нас есть готовый процесс — вот он»).

## Как предлагаю (AK-47, без шума)
- **Один лучший матч, не меню:** называю ОДИН самый подходящий скилл, одной строкой:
  «💡 кстати, для этого есть `/X` — запустить?». Не вываливаю список из пяти.
- **Уже делаю это сам → просто ИСПОЛЬЗУЮ скилл** (не спрашиваю разрешения каждый раз), и
  упоминаю, что прогнал через `/X`. Предложение-вопрос — когда выбор за Антоном.
- **Только на реальном совпадении.** Нет подходящего скилла или ход тривиальный/разговорный —
  молчу, не выдавливаю предложение ради галочки.
- **Уважаю отказы** (declined-decisions [internal]): скилл, который Антон уже отверг для этого случая,
  повторно не пред-лагаю.

## ⭐ Частный сильный случай — РАБОТА С ЛИДАМИ → всегда предлагай CRM-движок (Антон, 2026-06-27, «суперважно»)
Правило Антона (origin: anton, дословно): «главное САМ ВСЕГДА АКТИВНО ПРЕДЛАГАЙ все эти скиллы когда будем работать с лидами». Мы реверс-инжинирим боевой CRM Антона и **пересобираем 9 функций** в его стеке ([[crm-rebuild-plans-cc]]) — они окупаются только если всплывают в момент, когда Антон трогает лида/чат/аутрич. Поэтому **как только вижу лид-активность — сам, первым, называю подходящую CRM-функцию**, не жду спроса:

| Что Антон делает (триггер) | Что предлагаю (CRM-функция / скилл) | Слой |
|---|---|---|
| открыл/обсуждает лид-чат или сообщество | **Слушатель** (сенсор: ключевые слова/упоминания → алерт) · **Анализатор участников** (кто «болтуны»/спикеры = тёплые) | 🟢 сенсор |
| у лида скоро звонок / готовит встречу | **Напоминания о звонках** (Calendar+leads.db) · `/intro` (создать группу с лидом) | 🟢/🟡 |
| смотрит воронку / «на каком этапе лид» | **Статус-воронка** (`check_messages`) · `/pipeline` дашборд | 🟢 сенсор |
| хочет дотронуться до базы / разогреть | **Дрип-рассылка** · **Холодный дрип** · **Лёгкое присутствие** — всё через дневной бюджет 3-5/день (telegram-safety [internal]) | 🟠 дрип |
| новый человек зашёл в чат | **Привратник** (welcome-DM, draft-first) | 🟡 вовлекатель |

- **AK-47-подача та же:** один лучший матч одной строкой «💡 для этого есть `<функция>` — собрать/запустить?»; сенсоры (read-only) могу просто запустить; дрип/вовлекатели = draft-first + Tier-2 на саму отправку.
- **Пока функция ещё строится** (не все 9 готовы — статус в `_Dashboards\CRM-Rebuild-Tracker.html`) — всё равно называю её и предлагаю «собрать сейчас?» (это и есть «по очереди»). Готова → предлагаю «запустить?».
- **Анти-бан зашит:** любая 🟠 дрип-функция идёт через общий `crm-engine\budget.py` (3-5/день/аккаунт), не пулемёт.

## Граница и связи
- **Это про СУЩЕСТВУЮЩИЕ скиллы (использовать).** Зеркало — skill `skill-gap`, который про то,
  каких НОВЫХ скиллов не хватает (построить). Не путать: тут «вот кнопка», там «давай сделаем кнопку».
- Если вижу, что под повторяющееся действие скилла НЕТ — срабатывает evaluate-recurring-into-routine [internal]
  (предложить завести скилл/рутину), а не молчать.
- Усиливает minimize-user-time-autonomy [internal] (готовая кнопка экономит время Антона) и общую
  проактивность (anton-working-preferences [internal]).

## Детерминированное усиление — ВСТРОЕНО (Антон «+» 2026-06-27)
`UserPromptSubmit`-хук `skill_suggest_hook.py` (+`.cmd`) по ключевым словам матчит сообщение
Антона против триггеров скиллов и инжектит модели строку «💡 подходит `/X`» — детерминированный
бэкстоп к «забыл просмотреть 40 скиллов» (0 токенов, exit-0 на любой ошибке, молчит на слэш-
командах/без матча). Это СТРАХОВКА, не замена суждения: модель потом по анти-шум-правилу решает,
показывать ли Антону. Зарегистрирован 4-м UserPromptSubmit-хуком в `settings.json`. Только FULL-
машины (ведомые-потребители НЕ исполняют hub-хуки — leader/follower governance); Mac нужен `.sh`-шим.
**Ведомые — OPT-IN (Антон разрешил 2026-06-27):** хаб НЕ пушит хук тихо (это был бы бэкдор) — он ПРЕДЛАГАЕТ, а оператор ведомой машины САМ ставит с согласия (файлы на рельсе `[шина]/_transit/skill-suggest-hook/`: `.py` + `.cmd` для Win / `.sh` для Mac + `skill_suggest_selftest.py`). Это сохраняет governance (нет тихого hub-пуша) и расширяет покрытие. Само-тест: `python skill_suggest_selftest.py` → строка `SELFTEST… PASS/FAIL` в шину.
