**Правило:** КОГДА мы НАЧИНАЕМ любую активность — новый проект, дело, задачу, общение с лидом, подготовку встречи, ЛЮБОЕ действие на тему — → СНАЧАЛА проверяем ВСЁ, что у нас уже есть по этой теме во всём «Втором мозге»: и по всему волту, и в RAG-индексе. Только после этого recall'а — действуем. Не начинаем с нуля, если что-то по теме уже лежит у нас.

**Как именно (минимум, по закону «дешёвый инструмент первым»):**
- **Смысл (RAG):** `python [путь владельца] "<тема>"` или skill `/ask` — что мы про это думаем / писали / обсуждали.
- **Точно по волту:** grep/поиск по людям, лидам, заметкам, концептам; факты — из SQLite-слоёв (Platinum CRM, `browser_history.db` = «что Антон смотрел по теме», и т.п.).
- Сначала достаём дёшево всё, что уже знаем, и только потом тратим силы/токены на новое.

**Приоритетный случай — ЛИД (домен #1):** перед любым контактом или подготовкой по лиду — поднять его карточку в Platinum CRM + всё, что Антон про него и про тему писал, обсуждал и **гуглил** (история браузера). Пример: готовимся писать лиду про defense-tech → сначала `/ask` по теме + карточка лида + история браузера по теме → пишем уже зная контекст, а не вслепую.

**Касается и НАШИХ собственных задач в Claude Code (Антон, 2026-06-12):** всё, что мы обсуждаем и делаем вместе в диалогах Claude Code — это тоже «активность». Прежде чем браться за обсуждаемую задачу → проверить волт на **ценные инструкции по теме**: правила Библии (`reglament-*`/`protocol-*`), решения (`02-Decisions`), протоколы (`05-Resources/Protocols`), концепты И **прошлые сессии Claude Code** (`01-Conversations/Claude`). А вдруг там уже лежит инструкция / решение / контекст, как именно это делать — не начинаем с нуля то, по чему в волте уже есть указание. Пример: Антон в сессии просит «настроить импорт X» → сначала `/ask` + поиск по волту → находим прошлое решение/протокол по X → делаем по нему, а не заново.

**Зачем:** наш «Второй мозг» полезен, только если в него реально ЗАГЛЯДЫВАЮТ перед делом. Данные «учитываются» не сами по себе — а потому что эта проверка обязательна на старте каждой активности.

**Особый случай — ВОЗВРАТ к старой теме / ИНЦИДЕНТ (заострение, 2026-06-26):** когда всплывает НЕ новая тема (инцидент, знакомая система, «мы про это уже говорили») — recall не просто желателен, а **обязателен ПЕРВЫМ шагом**: тема может быть **уже решена**, и расследование с нуля рискует дать ложный вывод и навредить. И факт о состоянии системы бери из **живого источника, не со стале-копии на диске**. Канон: [[reglament-snachala-recall-potom-kopay-i-istina-iz-zhivogo-istochnika]].

## 🛑 Триггерные формулировки — где правило срабатывает ОБЯЗАТЕЛЬНО

Активность ≠ только «начать проект» или «писать лиду». Это ЛЮБОЙ из паттернов ниже. Перед ответом — `/ask` + grep волта **первым**, до составления чего-либо:

- «найди / расскажи / какие способы / как сделать X / какие варианты Y»
- **«напиши промпт / составь промпт / задание для другой ИИ / research-prompt по теме X»** ← легко принять за креативное письмо и проскочить recall. НЕ проскакивать.
- «давай сделаем / запустим / настроим X» (даже если X кажется новым — у нас может уже быть прошлая попытка / решение)
- «надо доставать данные из X», «надо интегрировать X», «надо обработать X-файлы»
- ЛЮБОЙ вопрос «сколько токенов / денег / времени стоит» на конкретную задачу — сначала проверь, не сделана ли она уже (тогда стоит 0)

**Правило большого пальца:** если вопрос про **тему**, а не про синтаксис тулзы — recall ПЕРВЫМ.

## 📌 Грабли-пример: 2026-06-13 (ChatGPT-export промпт)

**Что было:** Антон попросил «напиши промпт для ИИ, чтобы найти все способы доставать артефакты из ChatGPT». Я сразу написал длинный (~600 слов) промпт для внешней ИИ — БЕЗ recall'а волта.

**Что recall дал бы за 0 токенов LLM:**
- Папка `01-Conversations\ChatGPT` уже **СУЩЕСТВУЕТ** в волте с 17 категоризированными подпапками.
- `obsidian-vault.md`: **уже импортировано 2539 заметок ChatGPT** в волт (через OpenAI Export Data JSON).
- `vault-health-check.md`: 1241 файл с битым `�` — recoverable через re-import из JSON-оригиналов (значит JSON-оригиналы лежат в `_originals` и нужен **инкрементальный** re-import, не «с нуля»).
- `provenance-attribute-real-author`: 897 ChatGPT-дистилляций уже размечены `authored_by: ai`.
- Голосовая нота Антона 2026-05-28: «Я решил пока ручками копировать всё это из ChatGPT в NotebookLM» — то есть про **boundary canvas/projects/файлов** Антон уже сам знает, что официальный JSON их не везёт.
- Прошлый диалог про экспорт чатов упомянул расширение **«Save ChatGPT to Obsidian markdown file»**.
- Прошлый диалог «Автоматизация переноса диалогов из ChatGPT в NotebookLM» уже разбирал практики и риски.

**Правильный вопрос после recall'а** — НЕ «как с нуля», а: (1) инкрементальный re-import новых чатов поверх существующих 2539 (паттерн `telegram-reimport`), (2) что делать со **слепыми зонами** официального экспорта (Canvas, DALL·E-картинки, загруженные/созданные файлы, Memory, GPTs, Projects), (3) локальная БД desktop-приложения ChatGPT на Windows — это правда новый вопрос.

**Вывод:** длинный промпт оказался **в 5-10 раз шире, чем реально нужно**, потому что половина ответа лежала во втором мозге. Грабли — не «забыл правило», а «не распознал триггер»: парсил «напиши промпт» как креативную задачу, а не как «новая активность по теме X». Триггер выше теперь явный — чтобы не повторилось.
